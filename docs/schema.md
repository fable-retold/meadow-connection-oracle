# Schema &amp; Table Creation

Meadow Connection Oracle can generate and execute `CREATE TABLE`, sequence, trigger, and index statements from Meadow schema definitions. This lets you bootstrap an Oracle database directly from your model without writing DDL by hand, and it transparently handles the differences between modern (12c+) and legacy (11g) Oracle.

## Generating a CREATE TABLE Statement

Pass a Meadow table schema object (with `DataType` columns) to `generateCreateTableStatement()`:

```javascript
let tmpSchema = {
    TableName: 'FableTest',
    Columns: [
        { Column: 'IDFableTest',   DataType: 'ID' },
        { Column: 'GUIDFableTest', DataType: 'GUID' },
        { Column: 'Title',         DataType: 'String', Size: '256' },
        { Column: 'Description',   DataType: 'Text' },
        { Column: 'IDAuthor',      DataType: 'ForeignKey' }
    ]
};

let tmpSQL = _Fable.MeadowOracleProvider.generateCreateTableStatement(tmpSchema);
```

On a modern (12c+) connection in the default unquoted mode this produces:

```sql
CREATE TABLE FableTest
    (
        IDFableTest NUMBER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
        GUIDFableTest VARCHAR2(255) DEFAULT '00000000-0000-0000-0000-000000000000' NOT NULL,
        Title VARCHAR2(256) DEFAULT ' ',
        Description CLOB,
        IDAuthor NUMBER DEFAULT 0 NOT NULL
    )
```

## Meadow Data Types

| Meadow Type | Oracle Type | Default | Notes |
|-------------|-------------|---------|-------|
| `ID` | `NUMBER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY` | -- | 12c+ identity. Legacy mode emits `NUMBER PRIMARY KEY` plus a sequence + trigger |
| `GUID` | `VARCHAR2(Size)` | `'00000000-0000-0000-0000-000000000000'`, `NOT NULL` | Size defaults to 255 if omitted |
| `ForeignKey` | `NUMBER` | `0`, `NOT NULL` | |
| `Numeric` | `NUMBER` | `0`, `NOT NULL` | |
| `Decimal` | `NUMBER(Size)` | -- | Size is the precision spec (e.g. `'10,2'`) |
| `String` | `VARCHAR2(Size)` | `' '` (single space) | Nullable; Oracle treats `''` as NULL |
| `Text` | `CLOB` | -- | Returned as a string (driver `fetchAsString`) |
| `DateTime` | `TIMESTAMP` | -- | |
| `Boolean` | `NUMBER(1)` | `0` | Oracle pre-23c has no table BOOLEAN |
| `JSON` | `CLOB` | -- | Stored as text; stringified on write, parsed on read |
| `JSONProxy` | `CLOB` | -- | Uses the column's `StorageColumn` name |

Any column whose `DataType` is not in this list is skipped.

### Why these defaults

Two choices are Oracle-specific:

- **`String` defaults to a single space and is nullable.** Oracle stores an empty string as `NULL`, so a `NOT NULL` column defaulting to `''` would violate its own default. A single-space default sidesteps this.
- **`Boolean` is `NUMBER(1)`.** Before Oracle 23c there is no table-level boolean type. `0`/`1` matches how the FoxHound Oracle dialect emits boolean literals.

### Identifier quoting

By default identifiers are emitted **unquoted**, which Oracle folds to UPPERCASE. Set `Oracle.QuoteIdentifiers: true` to wrap every identifier in double quotes and preserve case:

```sql
CREATE TABLE "FableTest"
    (
        "IDFableTest" NUMBER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
        ...
```

The schema provider and the FoxHound Oracle dialect **must** use the same `QuoteIdentifiers` setting, or generated queries will not resolve against the created tables.

## Modern vs. Legacy Identity

`generateCreateTableStatements()` (plural) returns an ordered array of all the statements needed to materialize a table.

On a **12c+** connection (or with `LegacyIdentity: false`) this is a single `CREATE TABLE` using a `NUMBER ... GENERATED BY DEFAULT AS IDENTITY` column.

On a **legacy 11g** connection (or with `LegacyIdentity: true`) the `ID` column becomes a plain `NUMBER PRIMARY KEY`, and two more statements are appended:

```sql
-- 1. the table (ID is a plain NUMBER PRIMARY KEY)
CREATE TABLE FableTest ( IDFableTest NUMBER PRIMARY KEY, ... )

-- 2. a sequence
CREATE SEQUENCE SEQ_FableTest START WITH 1 INCREMENT BY 1 NOCACHE

-- 3. a BEFORE INSERT trigger that populates the key when it is NULL
CREATE OR REPLACE TRIGGER TRG_FableTest
    BEFORE INSERT ON FableTest
    FOR EACH ROW
    WHEN (NEW.IDFableTest IS NULL)
BEGIN
    SELECT SEQ_FableTest.NEXTVAL INTO :NEW.IDFableTest FROM DUAL;
END;
```

This keeps the dialect's `RETURNING` clause working identically across Oracle versions. The connection provider auto-detects which path to use from the server version on connect; you can force either path with the `LegacyIdentity` flag.

## Creating a Single Table

Generate and execute the create-table statements against the connected database, with retry:

```javascript
_Fable.MeadowOracleProvider.createTable(tmpSchema,
    (pError) =>
    {
        if (pError) return console.error(pError);
        console.log('Table created.');
    });
```

Statements run sequentially, and `ORA-00955` (object already exists) is swallowed per statement, so calling `createTable()` for an already-existing table is safe and reports success.

## Creating Multiple Tables

Pass a full Meadow schema (with a `Tables` array) to create all tables sequentially:

```javascript
let tmpFullSchema = {
    Tables: [
        { TableName: 'Author', Columns: [ /* ... */ ] },
        { TableName: 'Book',   Columns: [ /* ... */ ] }
    ]
};

_Fable.MeadowOracleProvider.createTables(tmpFullSchema,
    (pError) =>
    {
        if (pError) return console.error(pError);
        console.log('All tables created.');
    });
```

Tables are created one at a time (serial, not parallel).

## Dropping a Table

Oracle has no `DROP TABLE IF EXISTS`, so `generateDropTableStatement()` returns a PL/SQL block that swallows `ORA-00942` (table does not exist):

```javascript
let tmpDropSQL = _Fable.MeadowOracleProvider.generateDropTableStatement('FableTest');
```

```sql
BEGIN
    EXECUTE IMMEDIATE 'DROP TABLE FableTest CASCADE CONSTRAINTS';
EXCEPTION
    WHEN OTHERS THEN
        IF SQLCODE != -942 THEN RAISE; END IF;
END;
```

This generates the SQL only. Execute it against a pooled connection yourself:

```javascript
let tmpDropSQL = _Fable.MeadowOracleProvider.generateDropTableStatement('FableTest');

_Fable.MeadowOracleProvider.getConnection(
    (pConnError, pConnection) =>
    {
        if (pConnError) return console.error(pConnError);
        pConnection.execute(tmpDropSQL, [], { autoCommit: true })
            .then(() => pConnection.close())
            .then(() => console.log('Table dropped.'))
            .catch((pError) => { console.error(pError); pConnection.close(); });
    });
```

## Indices

The schema provider derives indices from your table schema:

- Each `GUID` column gets a **unique** index named `AK_M_<Column>`.
- Each `ForeignKey` column gets a **regular** index named `IX_M_<Column>`.
- A column with `Indexed: true` gets a regular index `IX_M_T_<Table>_C_<Column>`; `Indexed: 'unique'` gets a unique index `AK_M_T_<Table>_C_<Column>`. An `IndexName` property overrides the auto-generated name.
- Any explicit entries in the schema's `Indices` array are included (supports composite indices).

### Generating index statements

`generateCreateIndexStatements()` returns one object per index, each with a `Name`, a `Statement`, and a `CheckStatement` (a `USER_INDEXES` count query):

```javascript
let tmpIndexStatements = _Fable.MeadowOracleProvider.generateCreateIndexStatements(tmpSchema);
// [
//   {
//     Name: 'AK_M_GUIDFableTest',
//     Statement: 'CREATE UNIQUE INDEX AK_M_GUIDFableTest ON FableTest (GUIDFableTest)',
//     CheckStatement: "SELECT COUNT(*) AS INDEXEXISTS FROM USER_INDEXES WHERE INDEX_NAME = 'AK_M_GUIDFABLETEST' AND TABLE_NAME = 'FABLETEST'"
//   },
//   { Name: 'IX_M_IDAuthor', Statement: 'CREATE INDEX IX_M_IDAuthor ON FableTest (IDAuthor)', ... }
// ]
```

Because data-dictionary names are stored uppercase in unquoted mode, the `CheckStatement` compares against the uppercased names.

### Creating indices

`createIndex()`, `createIndices()`, and `createAllIndices()` execute the statements. Each index is checked against `USER_INDEXES` first and only created when it does not already exist:

```javascript
// All indices for one table
_Fable.MeadowOracleProvider.createIndices(tmpSchema,
    (pError) =>
    {
        if (pError) return console.error(pError);
        console.log('Indices created.');
    });

// All indices for every table in a schema
_Fable.MeadowOracleProvider.createAllIndices(tmpFullSchema,
    (pError) => { if (pError) console.error(pError); });
```

## Introspection

The provider can reverse-engineer Meadow schemas from the live `USER_*` data dictionary views (it queries the connecting user's own schema; there is no `dbo`-style prefix):

| Method | Returns |
|--------|---------|
| `listTables(fCallback)` | Array of table names from `USER_TABLES` |
| `introspectTableColumns(pTableName, fCallback)` | Meadow column definitions (maps Oracle types back to `DataType`) |
| `introspectTableIndices(pTableName, fCallback)` | Non-constraint indices from `USER_INDEXES` / `USER_IND_COLUMNS` |
| `introspectTableForeignKeys(pTableName, fCallback)` | Foreign-key relationships from `USER_CONSTRAINTS` |
| `introspectTableSchema(pTableName, fCallback)` | A full `{ TableName, Columns, ForeignKeys? }` schema for one table |
| `introspectDatabaseSchema(fCallback)` | `{ Tables: [...] }` for every table in the schema |

Type mapping during introspection is priority-ordered: IDENTITY columns map to `ID`, columns with a foreign-key constraint map to `ForeignKey`, then native types map by name (`NUMBER` with scale to `Decimal`, `NUMBER(1)` with an `is`/`has`/`deleted`/`active`/`enabled` name heuristic to `Boolean`, `TIMESTAMP`/`DATE` to `DateTime`, `CLOB`/`NCLOB`/`LONG` to `Text`, `VARCHAR2`/`CHAR` to `String`, with `Text` as the fallback).
